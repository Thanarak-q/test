คีย์มี 3 ส่วน ได้แก่ prefix <Value path="keyPrefix" code /> รหัสคีย์ (key id) และ secret
สองส่วนแรก (<code>{"<prefix>\_<key id>"}</code>) คือสิ่งที่หน้า API Keys แสดงเพื่อให้แยกคีย์ออกจากกันได้
ส่วน secret จะไม่แสดงอีก

## คีย์แสดงเพียงครั้งเดียว

ระบบแสดงคีย์เต็มเพียงครั้งเดียวหลังสร้างเสร็จ เราเก็บเฉพาะค่า hash ของ secret
จึงไม่มีใครแสดงคีย์ให้คุณดูอีกได้ รวมถึงเราด้วย

**ทำคีย์หาย?** สร้างคีย์ใหม่ อัปเดตแอปพลิเคชัน แล้วเพิกถอนคีย์เก่า

## ข้อจำกัด

- มีคีย์ที่ใช้งานอยู่ได้ไม่เกิน <Value path="maxKeysPerUser" /> คีย์ต่อบัญชี ถ้าต้องการสร้างเพิ่ม
  ให้เพิกถอนคีย์เดิมก่อน
- ข้อจำกัดนับต่อบัญชี ไม่ใช่ต่อคีย์ การมีคีย์มากขึ้นไม่ได้ทำให้ได้จำนวนคำขอหรือโทเคนเพิ่ม

## ใช้ HTTPS เท่านั้น

คำขอที่ส่งผ่าน HTTP ธรรมดาจะถูกปฏิเสธด้วย `400` ตอนที่ API ได้รับคำขอแบบนี้
คีย์ได้วิ่งผ่านเครือข่ายโดยไม่เข้ารหัสไปแล้ว ให้ **เพิกถอนคีย์นั้น** สร้างคีย์ใหม่
แล้วเปลี่ยน client ไปใช้ `https://`

## อย่าใส่คีย์ไว้ในโค้ด

อย่า commit คีย์ และอย่าใส่คีย์ในโค้ดฝั่ง frontend แอปมือถือ หรือสิ่งใดที่ส่งถึงมือผู้ใช้
เพราะใครมีไฟล์นั้นก็มีคีย์ด้วย ให้อ่านคีย์จาก environment บนเซิร์ฟเวอร์ของคุณ

## การเพิกถอน

เพิกถอนคีย์ได้จากหน้า API Keys การเพิกถอนมีผลภายใน

<Value path="revokeWindowSeconds" unit="วินาที" />
คำขอที่ยืนยันตัวตนผ่านก่อนหน้านั้นอาจยังทำงานจนเสร็จ

## เมื่อยืนยันตัวตนไม่ผ่าน

การยืนยันตัวตนที่ไม่ผ่านทุกกรณี ไม่ว่าจะไม่มี header คีย์ผิดรูปแบบ ไม่รู้จักคีย์ secret ผิด
หรือคีย์ถูกเพิกถอน จะได้ `401` แบบเดียวกันหมด เราตั้งใจไม่บอกสาเหตุ
เพื่อไม่ให้เป็นประโยชน์กับคนที่พยายามเดาคีย์ ให้ตรวจว่าคัดลอกคีย์มาครบ
และคีย์ยังใช้งานอยู่ในหน้า API Keys
